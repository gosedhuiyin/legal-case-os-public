# 案件状态目录

`case-state.json` 是案件当前状态的唯一真值源。任何 Skill 或脚本必须先读取它，再通过原子写入更新；不得以聊天记忆、Markdown分析稿、文件夹名称或派生索引替代它。不同聊天窗口共享这一份状态，而不是各自积累一份“案件记忆”。

`audit-log.jsonl` 是只追加的事件链。它用于复核谁在何时通过何命令改变了哪些对象，不可被反向解释为当前状态。每条事件都绑定变更前后状态哈希和上一事件哈希。

初始化脚本会把模板标识 `M-TEMPLATE`、模板时间和环境替换为新案件值。原始材料只保存在 `00-originals/`，状态目录不得保存原件副本。

## `memory/` 目录

初始化或 `upgrade-state` 会在本案状态目录内建立：

```text
memory/
├─ indexes/           可重建检索索引
├─ cards/             可重建主题卡
├─ context-capsules/  某次任务实际加载的有限上下文及清单
├─ workflows/         程序工单的派生视图
└─ runs/              单次AI/脚本运行日志
```

这些内容随案件移动和备份，不写入系统级或全局产品记忆。它们不得复制原件全文、整段聊天或形成第二份规范状态；当前视图、索引和胶囊可以删除后从 `case-state.json` 与原始来源重建。`RunAttempt` 日志只能证明某次运行发生过，不能证明相应 `WorkflowInstance` 已完成。

## 读写模式

- `off`：不读取案件实体记忆；
- `file_scoped`：只读取点名文件/对象及直接关联；
- `relevant`：读取本任务相关切片、重大反证和未决期限；
- `reflect`：有界检索跨批次关联，结果仍为候选。

对应写入为 `none`、`candidate`、`commit`。候选不能直接变成正式事实、证据、已核期限、策略或新案件；`commit` 也不能越过现有律师门禁。

## 多窗口与恢复

每次读取同时取得 `focus.state_version`。凡命令要求 `--expected-state-version`，必须传入该窗口读取时的值；若其他窗口已经更新状态，旧窗口必须停止、重读和重新核对，不能覆盖新版本。批次、语义、反思和运行游标仅在成功事务后推进。

旧 v1.0 状态须先运行 `upgrade-state`，且升级前应备份案件目录。发生中断或怀疑游标不一致时运行只读 `reconcile-matter`，不要手工修改状态或审计链。

本目录只管理案件内状态和派生记忆。本项目没有 G5 执行器，不能在这里触发打印、发送、上传、送达或提交。
