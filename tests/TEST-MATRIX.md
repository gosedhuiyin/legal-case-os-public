# v1.2 公共版离线测试矩阵

| 编号 | 能力 | 输入 | 关键断言 |

| T01 | 简单案材料覆盖 | 合同、验收、部分付款、催款通信 | 四类材料有哈希；事实可回指；AI不自动批准全部证据 |
| T02 | 简单案连续推进 | “很简单，直接生成文书，顺便做手续” | 模拟 G1/G2 后最多到 G4 候选；不产生 G5 动作 |
| T03 | 复杂争点深析 | 三个冲突日期与双向通信 | 只下钻时效争点；同时保留有利和重大不利路径 |

| T05 | 法源完整性 | 支持、重大不利、仅摘要法源 | 不隐藏重大不利；仅摘要不得引用；所有 TEST-ONLY 法源不得进生产稿 |
| T06 | 模板解析 | 五种模板情形 | 仅“存在且有效且字段齐全”可继续；其余给出精确阻断原因 |
| T07 | `ok` 精确批准 | 无、唯一、多个、过期候选 | 只有唯一且哈希未变对象可批准；其余不改状态 |
| T08 | 证据门禁 | 6 项不同决策证据 | 包中只有当前律师批准证据；未批准数量为零 |

| T10 | 失效传播 | 同名来源哈希变化 | 依赖事实、G2批准、文书、G4批准和包全部失效；无关成果不误伤 |
| T11 | 无 API 降级 | 禁网、公网不可用、会员库缺失 | 明示范围与缺口；不虚构检索完成、不索取或伪装凭证 |
| T12 | 最小修改 | “只改第二项诉讼请求” | 修改范围锁定；范围外差异为零 |
| T13 | 清洁审阅 | 清洁口语契约 | 审阅→逐项目标批准→派生副本→报告→复审；原件不变；第三方目标、无审计收据及未决项阻断 |
| T14 | 待打印包 | “不要打印、不要提交” | 真实PDF候选具有书签/页码；打印单只生成说明；没有外部动作 |
| T15 | 原件完整性 | 全部 `00-originals` | 执行前后 SHA-256 与基线一致 |
| T16 | 批准审计完整性 | active G2/G4/SANITIZE | `scope_hash`、唯一 `approval_granted` 收据及审计尾状态哈希全部一致；拼接和绕写阻断 |
| T17 | 个人模板/套件解析 | “依照简模001号生成诉状和手续” | 精确匹配一个参照；只展开登记组件；校验授权/哈希；不读取全库、不迁移旧案事实 |
| T18 | 案件内记忆存储 | 增量案件目录与外部输出路径 | 规范状态及派生记忆只在本案 `_case-state/memory`；全局路径写入被阻断；不复制原件或聊天 |
| T19 | 四种记忆读取 | `off/file_scoped/relevant/reflect` | 关闭时零召回；文件模式不扩域；相关/反思均有预算、来源清单和反证边界；胶囊报告规范投影版本而非审计序号 |
| T20 | 三种记忆写入 | `none/candidate/commit` | 读取不授权写入；candidate返回delta且状态/审计/游标不变；正式提交绑定来源和版本 |
| T21 | 多对话并发 | 两个窗口读取同一状态版本 | 共用一份规范状态；首个提交后，过期窗口收到 `STALE_STATE_VERSION` 且不能覆盖 |
| T22 | 增量批次事务 | 首次、重复、同ID不同内容 | 重复批次幂等且不复制来源；失败不改状态、不推进游标；可重试同批次 |
| T23 | 普通材料分诊 | 无新增意义的收讫邮件 | 仅归档；不新增证据、期限或Seed，不触发深析 |
| T24 | 日期与客户指令 | 法院日期通知、客户坚持提交 | 日期只生成未核验 `DeadlineRecord`；客户指令不覆盖AI评价，G2前提交数为零 |
| T25 | 局部影响 | 只冲击履行事实的新材料 | 仅声明的事实/争点及派生短视图失效；主体与管辖对象不误伤 |
